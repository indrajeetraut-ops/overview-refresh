## Contract and data flow that matter

- Synthetic stages use schema-versioned YAML in [`config/synthetic`](../../config/synthetic). The checked-in example makes 100 fake users, rosters 50 in three Teams, then covers 60 calendar dates from 2026-07-01 through 2026-08-29. Team and Project **names** are operator-facing selectors; stable internal IDs are saved in artifacts. Profile and usage seeds are separate. [`forecast.yaml`](../../config/forecasting/forecast.yaml) selects Organization `talium.ai` and Team `team1` by default; its Project example is commented out.
- YAML input paths resolve relative to the YAML file. CLI `--config`, `--output`, and Plotly `--run` paths resolve relative to the caller's working directory. Shell wrappers set `PYTHONPATH` for `forecast.*` plus the repository `src` (including shared JSON logging). New output paths are required; existing outputs are refused. CLI success summaries go to stdout, structured logs to stderr. Exit `0` means success, `2` input/partial analytical result, and `1` operational failure, with command-specific details in the operator guide.
- A daily usage row retains date, Organization, optional Team/user/Project attribution, agent type, model, billing mode, and the five token types (`input` is uncached input only; `cache_write_5m`, `cache_write_1h`, `cache_read` and `output` are separate). Coverage distinguishes an absent usage row on a completely observed day (zero activity) from missing collection (unknown). Organization, Team, and Project are overlapping views; never sum these scope totals as independent consumption.
- A forecast request uses an optional last completed `origin` (default: the dataset's declared end) and a calendar `week` or `month` window with `offset`/`periods`. Config selects Team/Project **names**, history/startup rules, ETS, allocation, uncertainty paths/seed, and workers; the horizon is on the CLI. `--validate-only` checks inputs, scope/history eligibility, and workload without fitting or writing output. It cannot certify numerical fit success.
- Forecasting fits each scope/model total with additive ETS, using the documented level-only/weekly seasonal fallbacks; recently inactive series can carry explicit zero paths. It samples aligned historical residual vectors across active models **within each scope** so same-column paths can later be priced together. Recent joint agent/category shares split total-token expectations; shares are fixed across the horizon. Negative simulated values are corrected only within the configured tolerance. See the release contract for numerical, history, resource, and partial-result rules.
- A completed synthetic output has `config.yaml`, `report.md`, `manifest.json`, stage JSONL files, and saved input snapshots where applicable. A completed forecast has `resolved_config.yaml`, `request.json`, `report.md`, `daily_expected.jsonl`, `period_summary.json`, `allocations.json`, `diagnostics.json`, `paths/index.json`, `paths/*.npy`, `charts/*.png`, and `manifest.json`. A manifest is written last; absence of a complete manifest means the directory is not a valid run. `paths/index.json` is authoritative for identity/date/sample ordering. The `.npy` arrays are float64 `(saved dates, sample IDs)` and [`load_run`](../../src/forecast/forecasting/artifacts.py) verifies manifest, identity, paths, shape, numeric values, and checksums before consumers use them. Period quantiles come from full-path period sums, not sums of daily or model quantiles. A partial analytical run is still a readable completed artifact set; its incomplete scope totals are not complete results.
